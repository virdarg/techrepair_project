# Учёт ремонта техники (Python + Tkinter + SQLite)

## Запуск

1. Нужен Python 3.10+; сторонние пакеты не требуются.
2. Запустите `python main.py`.
3. При первом запуске рядом с файлами автоматически создаётся `techrepair_app.db`.

Демо-аккаунты: `admin / admin123` (отчёты и аудит) и `user / user123` (пользовательский режим). Новые аккаунты регистрируются в окне входа.

## Структура

- `main.py` — Tkinter, навигация и сообщения.
- `business_logic.py` — проверка правил, роли и сценарии приложения.
- `data_access.py` — схема НФ3, представления, индексы, запросы, транзакционные процедуры и SQL UDF.
- `techrepair_triggers.sql` — контроль конфликтов записи и AFTER-аудит таблиц `appointments` и `techs`.

База включает пользователей, типы устройств, технику, специалистов, услуги, записи, связующую таблицу услуг записи и аудит. Владелец записи выводится через выбранную технику, а не дублируется в таблице записей. Связь M:N между записями и услугами реализована через `appointment_services`. Витрины: `v_appointment_details` и `v_service_report`; индексы ускоряют поиск по времени, специалисту, владельцу техники и дате аудита.

## Особенность SQLite

SQLite не имеет встроенных `CREATE PROCEDURE` и табличных пользовательских функций, а также не поддерживает `TRY/CATCH`/`THROW` в синтаксисе SQL Server. Поэтому процедуры `proc_*` реализованы Python-функциями слоя Data Access, где транзакции используют `BEGIN IMMEDIATE` / `COMMIT` / `ROLLBACK` и обработку исключений. Две SQL-скалярные UDF (`fn_is_valid_datetime`, `fn_duration_hours`) регистрируются при открытии подключения. Наборы строк для табличных функций имитируют `tvf_user_appointments` и `tvf_service_summary`; ограничения, конфликт времени и аудит исполняются триггерами SQLite. `RAISE(ABORT, ...)` — ближайший нативный аналог `THROW`.

Для проверки схемы откройте `techrepair_app.db` в SQLTools SQLite или SQLite Viewer после первого запуска.
